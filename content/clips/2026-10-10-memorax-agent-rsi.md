## 一句话概括

MemoraX 提出：RSI 真正卡住的地方不是模型会不会干活，而是**上一次的经验能不能变成下一次的起点**——于是把记忆拆成「写入（可学习的策略）/ 迁移（内容与访问结构解耦）/ 反馈优化（记忆贡献归因）」三段，用 Agentic RL 训练一个专用记忆模型，在长程 Coding、金融分析、IMO 级数学题上给出通过率 +20%、成本 -98% 一类的自报数字。

## 核心要点

**一、立论：记忆是 RSI 的地基**

文章的核心提问是「**AI 如何让过去的探索与试错真正成为下一次进步的基础，而不是每次面对新任务都从头开始**」。在这个框架下，记忆写入与检索是两个衔接环节：写入要从复杂执行轨迹里识别出**有效方法、失败结论及其适用条件**；检索要按新任务需求找到适用的历史方法与关键证据，避免经验遗漏与错误迁移。任务反馈再反过来检验经验价值，并把有效反馈用于记忆基础模型训练。

**二、从任务中学习：把「记忆写入」建模成一个可学习策略**

关键判断是：**记忆不是摘要与压缩问题**。原文说得很直白——「准确概括过去，并不意味着能够有效支持未来」。所以写入时不仅要判断什么值得留，还要一并保存**验证依据、环境约束与适用条件**。

MemoraX 的做法：把记忆写入建模为**面向未来任务收益的可学习策略**，建一套「环境构建 → 数据采集 → 样本构造 → 规模化 Agentic RL 训练」的流水线。在可交互、可验证的任务环境里采集执行轨迹、记忆使用记录与验证反馈，构造「写入决策 ↔ 后续使用效果」的关联样本；奖励信号按**后续任务的完成质量、执行效率与重复试错情况**设计。优化目标从"提炼得准不准"延伸到"对未来任务有没有实际影响"。

**三、从经验中迁移：把记忆内容与访问结构解耦**

两层设计：
- **结构层**：记忆内容与访问入口分离，按当前任务动态调整访问入口与关联关系，让同一份历史信息适应不同使用需求；
- **检索层**：用模型训练学「当前任务需求 ↔ 历史关键证据」的匹配关系，做**细粒度证据识别 + 相似记忆消歧**，目标是区分「**主题相关**」与「**证据正确**」——这句是全文最值得记的一句；
- **使用层**：结合当前任务状态与执行进展，把通用经验转成**带明确目标、操作约束和验证标准的行动指导**，并随任务阶段动态调整。

**四、从反馈中进化：Memory Credit Assignment（记忆贡献归因）**

文章自己点名这是核心挑战：**长程任务可能调用多条历史经验，但哪些真正影响了决策，哪些只是被读取却未发挥作用？即使任务最终成功，如何判断不同记忆各自的贡献？** 解法表述为：把记忆版本、实际使用记录与任务执行反馈关联起来，追踪历史经验是否真的参与了行动、以及使用后的表现与验证结果，据此保留强化有效经验、修正失效经验，并把这些反馈喂回记忆基础模型训练。

⚠️ 这是全文最关键、也最空的一节——只给了"要追踪、要关联、要评估"的方向，没有给任何可复现的归因算法。

**五、三类任务的实验结果（全部自报）**

| 场景 | 设置 | 结果 |
|---|---|---|
| 长程复杂 Coding | 通信/金融/物流等 5 大行业、13 项工业级系统开发任务，78 次开发运行，总时长 300+ 小时（后文同实验写 335 小时），单次最长 >12 小时 | 通过率 **+20%**，主 Coding Agent 累计 Token **-20%** |
| └ Memory Model–Driven RSI | 专用记忆模型从执行轨迹与在线反馈中提炼、更新**程序性记忆**，Agent 系统负责应用，形成「提炼 → 应用 → 验证 → 更新」闭环 | 多轮迭代后程序性记忆质量 **+10%** |
| └ 案例 AccessSentinel | 构建企业级权限控制系统，需严格安全约束 | 三次运行平均通过率相对 **+45%**，主 Agent Token **-66%** |
| 复杂金融分析 | FinRank 基准：制药/油气/汽车等行业 22 家美国上市公司真实财报 | 证据链召回率「接近 100%」，较 CodeX 准确率 **+20%**，成本 **-98%**；另一处写 36 轮 RSI 迭代后召回率 **96.49%**、准确率 **33.33% → 73.33%** |
| 复杂数学推理 | Matilda 16×16（IMO 级组合优化）：用最少矩形覆盖 16×16 网格中的 240 个方格，每行每列恰好留一个空洞，空洞位置约 20.9 万亿种排列 | 约 4 小时、600+ 次模型调用找到经验证的 **21 块矩形最优解**；较 OpenAI Codex 求解时间 **-13%**、成本 **-98%** |

数学那个案例的过程值得单独看：系统先找到 27 块、23 块候选，但**23 块的全局最优性论证被独立审计否决**；记忆把「可行解 ≠ 最优解」这条验证反馈写回后调整建模方法，把空洞位置与矩形边界约束统一纳入搜索，才先后找到 22 块、21 块。文中把它拆成「记忆自纠错 / 策略自优化 / 记忆再迭代」三步。

## 金句

> AI 如何让过去的探索与试错真正成为下一次进步的基础，而不是每次面对新任务都从头开始？

> 准确概括过去，并不意味着能够有效支持未来。

> 经验能够被保存，并不意味着它能在新任务中发挥作用。

> 区分「主题相关」与「证据正确」。

> 历史经验并非始终有效。新的任务既可能验证已有方法，也可能暴露其局限。

## 质疑与核查

1. **稿件性质先行**：这是一篇由企业技术内容构成、经机器之心发布的稿子，**没有论文、没有开源、没有第三方复现**，全部指标自报。文中唯一"权威背书"是"在全球权威记忆榜单获得冠军"——榜单名字没给。

2. **同一实验的时长自相矛盾**：长程 Coding 那段先写「累计 78 次开发运行，总开发时长超过 **300 小时**」，隔两段复述同一批 13 项任务时变成「超过 **335 小时**」。一处笔误也好、两组不同统计也好，都说明数字未经统一校对。

3. **同一个指标给了两个值**：金融分析先说「证据链召回率**接近 100%**」，后文又说「经过 36 轮 RSI 迭代，证据召回率达到 **96.49%**」。"接近 100%"与 96.49% 不宜并列，取哪个会直接改变结论强度。

4. **对照组只写「Codex / CodeX」，且两个拼写交替出现**：没给模型版本、thinking 档位、工具权限、最大步数。在这种对比里，**对照组配置差异本身就能制造 20% 的准确率差和 98% 的成本差**——成本降 98% 尤其可疑，常见来源是换了更便宜的档位或大幅缩短上下文，而记忆复用省下的 token 未必占这么大比例。无 API 单价、无调用量，无法核算。

5. **样本量与迭代轮数**：FinRank 只覆盖 22 家公司，**36 轮 RSI 迭代**在同一批材料上反复优化召回与准确率，过拟合到这批财报与这组问题的风险没有被排除；"33.33% → 73.33%" 是同一批数据上的前后对比，不是独立测试集上的结果。

6. **数学案例的宣传口径要打折**：「空洞位置约 **20.9 万亿种排列**」这个数字本身是对的（16! = 20,922,789,888,000），但它被当作"难点"来渲染——真正的难点从来不是穷举空洞位置，而是**证明不存在更少的矩形方案**。这一点文章自己其实承认了（23 块的论证被独立审计否决），但标题式表述容易让人读反。另外「IMO 难度」是媒体式类比，Matilda 16×16 不是 IMO 真题。

7. **最关键的「记忆贡献归因」没有技术内容**：Memory Credit Assignment 被点名为核心挑战，正文只说"建立关联、追踪、评估、迭代"，**没有任何可复现的归因算法、基线或消融**。而这恰恰是整篇文章的立论支点——如果归因做不准，"按反馈优化记忆"就是一句空话。

8. **与既有信源的对照**：OpenAI 的 2028 年 3 月时间表、Jakub Pachocki 谈 RSI，与我库里 09-15 的 RSI 综述一致；**Anthropic「Claude 在约 26% 内部 AI 研发工作中主导」是新数据**，此前未见过，引用时需注明是 Anthropic 自报且口径是"内部研发工作"而非"全部工作"。
